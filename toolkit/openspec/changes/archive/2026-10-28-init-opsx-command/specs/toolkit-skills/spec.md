## ADDED Requirements

### Requirement: OpenSpec setup command
The toolkit SHALL include a command `jois-init:opsx`, the single file
`toolkit/commands/jois-init/opsx.md`, that sets OpenSpec up in the project it runs in. The `/opsx:*`
commands are generated by `openspec` and SHALL NOT be stored or patched by the toolkit. The command
SHALL, asking before each write: run `openspec init` when the project has no `openspec/` folder; make
sure the global `delivery` is `commands` and `workflows` lists propose, explore, apply, update, sync
and archive; merge its guidance into `openspec/config.yaml`; and run `openspec update`. It SHALL be the
only writer of that guidance, and the installer SHALL NOT touch `openspec/`.

#### Scenario: Fresh project
- **WHEN** the command runs in a project with no `openspec/` folder
- **THEN** it SHALL run `openspec init`, merge the guidance into the new `openspec/config.yaml`, and run `openspec update`

#### Scenario: Config has the project's own settings
- **WHEN** `openspec/config.yaml` already has `context`, `rules` or other `operations.*.guidance` entries
- **THEN** the command SHALL keep every one of them and add only its own block

#### Scenario: Re-run
- **WHEN** the command runs again and its block is already in `openspec/config.yaml`
- **THEN** it SHALL replace that block in place, between its begin and end comment markers, and SHALL NOT add a second copy

#### Scenario: Commit rule not installed
- **WHEN** `~/.claude/rules/jois-git-commit-hygiene.md` does not exist
- **THEN** the command SHALL say so and name `Install-Toolkit.ps1`, and SHALL NOT copy the rule itself

### Requirement: Guidance points at the commit rule
The guidance the command writes for `apply` and `archive` SHALL tell the agent to follow the
`jois-git-commit-hygiene` rule at each commit and SHALL NOT restate that rule's steps.

#### Scenario: One source for the commit steps
- **WHEN** the rule's confirmation steps change
- **THEN** only `toolkit/rules/jois-git-commit-hygiene.md` SHALL need editing

### Requirement: Jois command files are versioned
Each command file under `toolkit/commands/jois-git/` and `toolkit/commands/jois-init/` SHALL declare
`metadata.version` (semver) and `metadata.last_updated` (a date) in its frontmatter, and the docs
check SHALL fail and name a file where either is missing or malformed.

#### Scenario: Missing version
- **WHEN** `toolkit/commands/jois-git/stage.md` has no `metadata.version`
- **THEN** the docs check SHALL fail and name the file

#### Scenario: Setup command is checked too
- **WHEN** `toolkit/commands/jois-init/opsx.md` has no `metadata.last_updated`
- **THEN** the docs check SHALL fail and name the file

## REMOVED Requirements

### Requirement: Jois commands carry a version
**Reason**: It exempted the stored `opsx` commands, which no longer exist, and covered only `jois-git`.
**Migration**: Replaced by "Jois command files are versioned", which covers `jois-git` and `jois-init` with no exemption.

## MODIFIED Requirements

### Requirement: Slash commands source of truth
The repository SHALL keep every custom slash command under `toolkit/commands/`. Each entry directly
under it SHALL be either a single `.md` file or a folder of `.md` files used as a namespace, and is
the unit the installer acts on.

#### Scenario: Namespace folder is one unit
- **WHEN** `toolkit/commands/jois-git/` holds several command files
- **THEN** the installer SHALL treat `jois-git` as one command item and copy the whole folder

### Requirement: Commands are hidden from the session context
Every command file under `toolkit/commands/` SHALL declare `disable-model-invocation: true` in its
frontmatter, so its description is not loaded into a new session's skill listing while the user can
still invoke it by name. Skills SHALL NOT be given this flag by this requirement, and the `/opsx:*`
commands generated by `openspec` are not covered. The docs check SHALL fail and name any command file
without the flag.

#### Scenario: Command is hidden but runnable
- **WHEN** a new session starts with the commands installed
- **THEN** no command description SHALL appear in `/context`, and typing `/jois-git:stage` SHALL still run it

#### Scenario: Flag is missing
- **WHEN** a command file under `toolkit/commands/` lacks the flag
- **THEN** the docs check SHALL fail and name the file
