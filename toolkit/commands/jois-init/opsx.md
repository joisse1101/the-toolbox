Set OpenSpec up in the project this runs in. The `/opsx:*` commands are generated by `openspec`
and may live in this project or in `~/.claude`, so never edit, copy or regenerate them: all of ours
goes into this project's `openspec/config.yaml`. Ask about each write on its own, in plain words:
why it is needed, and whether it changes only this project or every project on the machine. Never
combine two writes in one yes/no.

## Steps

1. **Check the CLI.** Run `openspec --version`. If it is missing, say so and stop; do not install it.
   Note the version for the report.
2. **Init when missing.** If the project has no `openspec/` folder, ask: "This project has no
   OpenSpec folder yet. Create it with `openspec init`? It only adds `openspec/` here." Then run it.
3. **Check the workflows (read-only).** Run `openspec config get workflows` and note the result.
   - If it lists `apply` and `archive`, say nothing more; the report shows `workflows=ok`.
   - If either is missing, say in plain words that the commit-stop guidance will not take effect for
     the missing operation. Then ask separately whether to add it with `openspec config set
     workflows`, and say this changes a setting for every project on the machine. Change nothing
     without a yes. On a no, carry on to step 4.
   - Never read, set or require `delivery`, and never run `openspec update`.
4. **Merge the guidance.** This is the essential write: it adds our commit stops to this project's
   `openspec/config.yaml` and affects only this project. Ask first, then put the block below into the
   `guidance:` list of `operations.apply` and `operations.archive`, creating the keys when missing.
   - Keep everything else in the file: `schema`, `context`, `rules`, and any guidance the project wrote.
   - Wrap each block in the comment lines `# jois-init:opsx begin` and `# jois-init:opsx end`. If those
     markers are already there, replace what is between them in place; never add a second copy.
   - Show the diff (`git diff openspec/config.yaml`) and ask before keeping it. If the YAML no longer
     parses (`openspec status` or `openspec list` fails), restore the file and report.
5. **Check the commit rule.** The guidance points at `~/.claude/rules/jois-git-commit-hygiene.md`. If
   that file does not exist, say so and name `Install-Toolkit.ps1`. Do not create the rule yourself.
6. **Report in one line**, in this form, then add that the commit stops are advisory guidance: the
   global rule is what enforces them.

   ```
   OpenSpec 1.x | openspec/ present | workflows=ok | guidance: added | commit rule: found
   ```

   `openspec/` is `present` or `created`; `workflows` is `ok`, `missing apply`, `missing archive` or
   `fixed`; `guidance` is `added`, `replaced` or `unchanged`; `commit rule` is `found` or `missing`.

## The guidance block

One line per operation; the steps live in the rule, so do not copy them here. A hand edit between
the markers is overwritten on the next run.

`operations.apply.guidance`:

```yaml
      # jois-init:opsx begin (managed by /jois-init:opsx; edits here are overwritten)
      - "At the end of each concern, stop and follow the jois-git-commit-hygiene rule: stage by explicit path, show the summary and message, name a confirmation word, and end the turn. Never commit in the turn you stage."
      # jois-init:opsx end
```

`operations.archive.guidance`:

```yaml
      # jois-init:opsx begin (managed by /jois-init:opsx; edits here are overwritten)
      - "Follow the jois-git-commit-hygiene rule for the archive commit: stage by explicit path, show the summary and message, name a confirmation word, and end the turn. Never commit in the turn you stage."
      # jois-init:opsx end
```

Indent the lines to match the file. The two operations are separate lists, so each gets its own
markers.
