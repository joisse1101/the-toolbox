Set OpenSpec up in the project this runs in.

## Rules

- The `/opsx:*` commands are generated by `openspec` and may live in this project or in `~/.claude`.
- Never edit, copy or regenerate them.
- All of our guidance goes into this project's `openspec/config.yaml`.
- Ask about each write on its own, in plain words.
- Say why the write is needed.
- Say whether it changes only this project or every project on the machine.
- Never combine two writes in one yes/no.

## Steps

1. **Check the CLI.**
   - Run `openspec --version`.
   - If it is missing, say so and stop. Do not install it.
   - Note the version for the report.
2. **Init when missing.**
   - This applies if the project has no `openspec/` folder.
   - Ask: "This project has no OpenSpec folder yet. Create it with `openspec init`? It only adds `openspec/` here."
   - Then run it.
3. **Check the workflows (read-only).**
   - Run `openspec config get workflows` and note the result.
   - If it lists `apply` and `archive`, say nothing more. The report shows `workflows=ok`.
   - If either is missing:
     - Say in plain words that the commit guidance will not take effect for the missing operation.
     - Ask separately whether to add it with `openspec config set workflows`.
     - Say that this changes a setting for every project on the machine.
     - Change nothing without a yes.
     - On a no, carry on to step 4.
   - Never read, set or require `delivery`.
   - Never run `openspec update`.
4. **Merge the guidance.**
   - This is the essential write. It adds our commit guidance to this project's `openspec/config.yaml` and affects only this project.
   - Ask first.
   - Then put the block below into the `guidance:` list of `operations.apply` and `operations.archive`.
   - Create the keys when they are missing.
   - Keep everything else in the file: `schema`, `context`, `rules`, and any guidance the project wrote.
   - Wrap each block in the comment lines `# jois-init:opsx begin` and `# jois-init:opsx end`.
   - If those markers are already there, replace what is between them in place.
   - Never add a second copy.
   - Show the diff (`git diff openspec/config.yaml`) and ask before keeping it.
   - If the YAML no longer parses (`openspec status` or `openspec list` fails), restore the file and report.
5. **Check the commit rule.**
   - The guidance points at `~/.claude/rules/jois-git-commit-hygiene.md`.
   - If that file does not exist, say so and name `Install-Toolkit.ps1`.
   - Do not create the rule yourself.
6. **Report in one line**, in the form below.
   - Then add that the commit guidance is advisory.
   - The global rule is what enforces them.

   ```
   OpenSpec 1.x | openspec/ present | workflows=ok | guidance: added | commit rule: found
   ```

   The report fields take these values:
   - `openspec/`: `present` or `created`.
   - `workflows`: `ok`, `missing apply`, `missing archive` or `fixed`.
   - `guidance`: `added`, `replaced` or `unchanged`.
   - `commit rule`: `found` or `missing`.

## The guidance block

- Each guidance entry is one line.
- The steps live in the rule, so do not copy them here.
- A hand edit between the markers is overwritten on the next run.

### `operations.apply.guidance`

```yaml
      # jois-init:opsx begin (managed by /jois-init:opsx; edits here are overwritten)
      - "Hand each group of tasks, in file order, to the task-applier agent instead of implementing the tasks in this session. Brief it with the verbatim task texts, the files to read, what each task satisfies (the specs' requirement names) and how to verify it."
      - "Hand the final test task to the test-runner agent with the files the change touched. Count the tests as passed only when every command it reports shows exit code 0."
      - "Before the first dispatch, check that task-applier.md and test-runner.md are in ~/.claude/agents/ or this project's .claude/agents/. If one is missing, say so, name Install-Toolkit.ps1 and do not copy the agent yourself."
      - "The agents commit nothing and never edit tasks.md. Record each task's result from its report and tick its box yourself."
      - "Commit a finished concern without asking for a confirmation word only on a branch other than main or master, when the concern's tasks are done and nothing outside its own files is staged or edited. Stage by explicit path. Run no test between groups: the final test task is the only check that gates a commit. Never push; on main, master or a detached HEAD follow the confirmation-word path of the jois-git-commit-hygiene rule."
      # jois-init:opsx end
```

### `operations.archive.guidance`

```yaml
      # jois-init:opsx begin (managed by /jois-init:opsx; edits here are overwritten)
      - "Follow the jois-git-commit-hygiene rule for the archive commit: stage by explicit path, show the summary and message, name a confirmation word, and end the turn. Never commit in the turn you stage."
      # jois-init:opsx end
```

### Indentation

- Indent the lines to match the file.
- The two operations are separate lists, so each gets its own markers.
