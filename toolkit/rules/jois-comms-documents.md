# Documents

How to write markdown: specs, READMEs, skills, rules and notes. It applies to every markdown file you write.

## Structure

- Put the purpose or the result first.
- Give each topic its own header, and nest headers by hierarchy.

## Bullets

- Keep each bullet to one idea in one short sentence.
- Move a second idea into its own bullet or a sub-list.

## Words

- Define a technical term on first use unless the repo has a glossary or definitions page, then link to it.

## Next steps and certainty

- Name who owns each next step and by when.
- Mark what is known, what is assumed and what is unchecked, apart from each other.
