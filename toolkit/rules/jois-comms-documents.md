# Documents

How to write markdown: specs, READMEs, skills, rules and notes. It applies to every markdown file you write.

## Structure

Put the purpose or the result first. Give each topic its own header, and nest headers by hierarchy.

## Bullets and paragraphs

Use bullets only for parallel items that can be reordered without losing meaning, such as flags, file names or rules. Write explanations, reasons and cause-and-effect as a short paragraph, so that "because" and "so" stay attached to what they connect.

Read the bullet aloud. If it starts with "So", "Because" or "This", or only makes sense after the bullet before it, write a paragraph instead.

A list of fewer than three bullets is a sentence. A bullet with two sentences is a paragraph split wrongly.

A header holds a paragraph of content, not a single bullet. Write the paragraph, or drop the header.

For each bullet that remains, keep it to one idea in one short sentence. Move a second idea into its own bullet or a sub-list.

## Numbered lists

Use a numbered list only for steps a person does in order. For any other items, use bullets or a paragraph.

## Rewriting

When you rewrite existing text, check that each reason and each "because" in the old text is still in the new text.

## Words

Define a technical term on first use unless the repo has a glossary or definitions page, then link to it.

## Next steps and certainty

Name who owns each next step and by when. Mark what is known, what is assumed and what is unchecked, apart from each other.
