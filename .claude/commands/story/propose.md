description: Draft the stories, backlog edits and lexicon terms agreed in this session and write them to the proposals, the editor suggestions and the lexicon (new terms) or the lexicon suggestions (changes to existing terms) without a yes/no step
allowed-tools: mcp__backlog-tools__read_context, mcp__backlog-tools__search_stories, mcp__backlog-tools__read_file, mcp__backlog-tools__check_drafts
---

Propose the stories we just explored and write them to `proposals/<backlog file name>` now; write the changes agreed for stories already in the backlog as suggestions in `reviews/<backlog file name>` the same way, and the new terms agreed for the lexicon to `lexicons/<backlog file name>`; an edit, rename or delete of a term that exists is written as a suggestion in `lexicon-suggestions/<backlog file name>` for the user to apply.

1. First, before you read or draft anything: if `check_drafts` or any of `write_proposals`, `write_lexicon`, `suggest_lexicon_change` and `write_review` is not among your tools, stop. Say the session is read-only and which tools are missing, name `shape-stories.ps1` and `plan-stories.ps1` as the launchers that start a session with them, and read, draft and write nothing.
2. Load the `propose-stories` skill with the Skill tool and follow it for the input, the drafting rules and the writers (`write_proposals`, `write_review` for edits to backlog stories, `write_lexicon` for new terms and `suggest_lexicon_change` for editing, renaming or deleting one), with one change: **skip its "Confirm before writing" yes/no step**. This command is the user's go-ahead, so write in the same turn.
3. Draft from the conversation so far (the backlog and story from the opening prompt, the agreements reached while exploring). If nothing was agreed yet, say so and stop; do not invent stories, edits or terms. The `index` section is an index only (find related stories with `search_stories`, not by reading it); call `read_context` with the `storyId` and `storyTitle` to read a backlog story in full before patching or editing it, and read the proposals and lexicon with `read_file` (ignore benched proposed stories). Name stories to the user by Title and handle a Title mismatch as the skill's "Name stories by Title" says. Extra instructions from the user: $ARGUMENTS
4. Right before each writer call, print that writer's drafts in full, in the order they are written and with the numbers the skill uses (for patches and edits, old and new values; for new lexicon terms, their fields; for an edit, rename or delete of a term, the old and new values and the impact) so the user can see what is being written. Still split a story over the size limit first, and prefer a patch to a second story.
5. Before the first writer call, run `check_drafts` on everything you are about to write and fix what it reports (no question to the user is needed, but say what you changed). After **each** writer call, read that file back in the same turn (`read_context` for the review and the lexicon suggestions, `read_file` for the proposals and the lexicon), as the skill's "Verify every write" says, and call something written only when the read-back matches. A rejected call wrote nothing: fix the drafts and call again. If a read-back is missing something, say so and send again only the missing part.
6. Everything else in the skill stands: the lexicon first, then the term suggestions, then the proposals, then the edits; a call whose read-back matched is not run again; the backlog CSV is never touched.
7. End with the skill's Report.
