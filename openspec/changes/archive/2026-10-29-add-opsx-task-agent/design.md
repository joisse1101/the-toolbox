## Context

See proposal.md - Why. The constraints that shape the approach:

- `/opsx:*` commands are generated by `openspec` and must not be edited. The one hook the toolkit
  owns is the managed `guidance:` block that `/jois-init:opsx` writes into `openspec/config.yaml`.
  A guidance line is advice to the main session; nothing forces it to delegate.
- A subagent's tool calls and output do not reach the main conversation. `write-pr` reads
  `tasks.md` and runs visible in the conversation, so a subagent's report alone is invisible to it
  (it skips "summarized history"). `tasks.md` task results are a source it already reads.
- Claude Code starts subagents in the background by default, shows each as a row in a panel (Enter
  opens its transcript, `/tasks` lists them), and has no subagent timeout; `maxTurns` is the only
  limit and returns a partial result when hit. Frontmatter `PreToolUse` hooks work in an agent file.
  Live tool-call counters or timers are not documented.
- `check_toolkit.py` already lists `agents/*.md` in its versioned items; the installer, `targets.json`
  and the README do not know agents.
- `~/.claude/agents/` already holds `arch-checker`, `code-reviewer` and `sec-checker`, which the
  toolkit does not ship. Install and uninstall must leave them alone.

## Goals / Non-Goals

**Goals:**
- Keep each task's working detail out of the main window while the author can still see what is
  running and when a task is done.
- Make `write-pr` work from the reports with no change to its template or rules.

**Non-Goals:**
- Running tasks in parallel. Agents share one checkout and parallel dispatch splits the author's
  progress view; it can be added later if a real need shows up.
- A progress file or any streaming from the agent. The author watches the panel, the transcript and
  the ticks in `tasks.md`.
- Guaranteeing that `/opsx:apply` delegates. The guidance asks for it; the spec says so.
- Live end-to-end testing of the agent in an apply run. The author refines it by using it.

## Decisions

**1. One generic agent, `opsx-task-applier`, not one per concern.** The task text carries the
specifics, and one file means one set of limits and one report shape to keep correct. Alternative:
agents split by concern (code, docs, installer). Rejected: more files to keep in step with nothing
gained until a concern needs different tools.

**2. The main session writes `tasks.md`; the agent never does.** The report ends with a `result:`
clause, and the guidance has the main session copy it verbatim next to the task and tick the box.
`write-pr` already sorts a checked task with `(result: ...)` into a `tasks.md N.N, result recorded`
bullet, so it needs no change. Alternatives: teach `write-pr` a new "subagent report" source (changes
two commands that `check_toolkit` forces to stay identical); let each agent edit `tasks.md` (unsafe
if two ever run at once). The remaining risk is the copy: the agent writes the clause ready to paste
so the main session has nothing to rephrase.

**3. Tools `Read, Grep, Glob, Edit, Write, Bash`, a turn limit and two hooks.** `maxTurns: 30` is a
starting value to tune in use. The docs show no pattern syntax such as `Bash(git push:*)` for an
agent's tool list, so the limits that matter are enforced by hooks, as `write-pr` already does:
- a `Bash` hook that exits 2 when the command matches `git commit`, `git push`, or the `gh`
  command, with a message naming the rule;
- an `Edit|Write` hook that exits 2 when the target path is a change's `tasks.md`.
The hooks use the same `powershell -NoProfile -Command` form as the hook in `write-pr.md`. A narrow
`tools` list alone cannot stop `git commit`, because `Bash` is needed to run tests.

**4. A `blocked:` outcome.** A subagent may not be able to ask the user a question mid-task, so it
stops and reports `blocked: <question>` instead of guessing. The main session then asks the user and
dispatches again with the answer.

**5. Announce, then report.** The guidance line has the main session say, before each dispatch,
the task, the files expected, a rough estimate labeled as one, that there is no live timer, how to
open the transcript (panel row, Enter, or `/tasks`) and the turn limit; after each report, one line:
done, failed or blocked. The estimate is a guess from the task's size and the commands it will run;
it is never presented as a promise, because Claude Code has no subagent timeout to back it. The
ticks in `tasks.md` are the progress view across tasks, the transcript the view inside one.

**6. Installer treats agents like rules.** One `.md` file per item, a fourth `agents` entry in
`targets.json` and an `-Agent` parameter, so `Get-ItemHash.ps1`, state listing, no-silent-overwrite and
uninstall work unchanged. `check_toolkit.py` gains a check that each agent has `tools` (an omitted list
inherits everything); its version check already covers agent files.

## Risks / Trade-offs

- [The main session ignores the guidance and applies tasks itself] -> The spec words it as guidance;
  the agent and hooks do no harm when unused. Tune the wording after real use.
- [The main session rewords the `result:` clause and a result drifts] -> The agent writes it ready to
  paste, and the guidance says verbatim.
- [A hook regex misses a form of the command, such as `gh` inside a script] -> The hooks catch the
  direct command; the agent's tool list stays narrow and the main session's commit stop is the
  backstop. Check the hook scripts against sample tool-input JSON.
- [The `Edit|Write` matcher or the PowerShell hook behaves differently on Windows than the docs show]
  -> Check the hook commands directly with sample input; the author refines the rest in use.
- [The estimate is wrong] -> It is labeled, and the transcript and `maxTurns` bound the worst case.
- [`Bash` stays broad] -> Accepted for now: the agent has to run tests and builds.

## Migration Plan

Additive. Install the agent with `Install-Toolkit.ps1 -Agent opsx-task-applier.md`, then run
`/jois-init:opsx` in a project to add the delegation line to its `openspec/config.yaml`. To roll back,
delete the agent and re-run `/jois-init:opsx` from the previous toolkit version; the markers make the
block replace in place.
