## Context

See proposal.md - Why. Constraints that shape the approach:

- `/opsx:*` commands are generated by `openspec` and the toolkit must not edit, copy or regenerate them. The only toolkit-written channel into `/opsx:apply` is the `operations.apply.guidance` list in `openspec/config.yaml`, which `/jois-init:opsx` fills between begin and end markers. It is advice, so a session can ignore it.
- `jois-code:apply` is slice-only today. Its text and its spec ("Apply orchestrator command") still describe the older change form, so the live spec already lags the command. This change also rewrites those stale requirements (the command, reading the slice, announcing and briefing, and the review step) to match the slice-only command, because it rewrites the same requirements for the new names anyway.
- The agents carry slice vocabulary: the applier reads `UC-<slice>.md`, `Satisfies:` and `Verify:` lines and names `AC-` rows, and both agent descriptions name `/jois-code:apply`.
- The commit rule's apply clause allows a commit without the word only for a flow that applies a plan's tasks, on a branch other than `main` or `master`, with its checks passing.
- Tests for the applier hook read the agent file by path (`toolkit/tests/test_task_applier.py`).

## Goals / Non-Goals

**Goals:**
- One pair of agents that either apply workflow can use without edits.
- `/opsx:apply` sessions get both the dispatch advice and the full auto-commit conditions from the guidance block.

**Non-Goals:**
- Enforcing delegation in `/opsx:apply`. A change form of `/jois-code:apply` is the fallback and is a separate change.
- Changing hooks, tools, turn limits or models.
- Deleting old agent files for the user.

## Decisions

**1. Short names, no prefix.** `task-applier` and `test-runner` say what they do and carry no workflow name. Alternative: `jois-` prefix like the commands (rejected: the user asked for the plain names, and agents here are not prefixed except `jois-worker`).

**2. The brief carries the plan-specific meaning.** The agent text says "follow the brief for what each task satisfies and how to verify it" and keeps the report shape: files changed, commands run, manual checks, unverified, satisfies, `result:`, failures. For a slice the `jois-code:apply` brief already carries `Satisfies:`, `Verify:` and the `UC-<slice>.md` path, so its text gains a sentence saying so. For a change the guidance asks the session to pass the specs' requirement names and the group's tasks. Alternative: two agent variants (rejected: duplicate hooks and report rules, which drift).

**3. Hooks keep their behavior, with new names in the messages.** Only the error text changes ("task-applier never commits..."). The tests that match message text are updated with them.

**4. The guidance block grows from one line to a few.** Entries stay one line each, as the setup command requires. They cover dispatch, the test task, the agent check and the commit conditions. The commit line names the conditions because the rule's apply clause is ambiguous to a session that does not recognize its flow as one. The check that gates a commit is the test task alone, because that is how `jois-code:apply` already works and the tests run once, at the end.

**5. No migration code.** The installer treats each file as a unit, so the new files install as new items and the old ones stay. The install page tells the user to delete the old files. A command that still looks only for the old names is a rename miss: each command checks for the new names, and the old name alone counts as not installed.

**6. Version bumps.** `task-applier` goes to 2.0.0 and `test-runner` to 2.0.0 (the name is a breaking change), the `jois-code` commands and `jois-init:opsx` get a minor or patch bump as their files change.

## Risks / Trade-offs

- [Guidance is advisory, so `/opsx:apply` may still implement in the main session or still ask before committing] -> The commit conditions are stated in full so the rule has no ambiguity to fall back on. If sessions still skip the dispatch, add the change form of `/jois-code:apply`.
- [A machine with only the old agents breaks `jois-code:apply` after updating the command] -> The command says the new agent is not installed and names `Install-Toolkit.ps1 -Agent task-applier.md`. The install page tells the user to delete the old files.
- [A missed rename leaves a stale name in a command or a wiki page] -> A task greps the live files (everything outside `openspec/changes/archive/`) for the old names and `python scripts/check_docs.py` runs after the docs change.
- [The generated `/opsx:apply` text ignores the guidance order] -> Nothing blocks it, as the spec already says.

## Migration Plan

1. Merge the change. Run `Install-Toolkit.ps1 -Agent task-applier.md` and `-Agent test-runner.md`, and `-Command jois-code` and `-Command jois-init` for the updated commands.
2. Delete `opsx-task-applier.md` and `opsx-test-runner.md` from `~/.claude/agents/` and any project `.claude/agents/`.
3. Run `/jois-init:opsx` in each project to replace the guidance block.

To roll back, reinstall the previous toolkit version, which brings the old agent files back.
