# Proposal

## Why

The story-to-code flow has ten stages and no way to see it run end to end. To explain it, or to test an edited skill, a person has to build a project by hand, and the only sample data is a small backlog and slice under `toolkit/tests/story/fixtures/sample` that serves unit tests, not a walkthrough. A sample project that the toolkit can rebuild on demand, with the saved result of every stage, makes the flow easy to show and cheap to test, because the stages that cost real model tokens are recorded once instead of rerun each time.

## What Changes

- Add `toolkit/sample/story-to-code/`: a small habit and focus tracker app (Vite, TypeScript, Tailwind CSS, browser local storage), its wiki, a `CLAUDE.md` for the mock repo, and one saved result per stage of the flow.
- Add a PowerShell script, `build-mock-repo.ps1`, that builds a mock repo under `.scratch/mock-app/` (its own git repo on a non-main branch, the toolkit installed at project scope only) and can restore the repo to any saved stage.
- Keep the app deliberately incomplete. The baseline has a habit list with a daily check-off, a Pomodoro timer, a task category picker and saving to local storage. Category audio scapes, streaks, weekly stats, custom timer lengths and import/export are logged on a Future releases wiki page, so a rerun of the flow always has a feature to add.
- Generate the audio in code (Web Audio noise) so no recordings are bundled, and let a git-ignored `audio/` folder hold a person's own files.
- Record one real walk of the flow that adds one future feature and ends archived, and commit each stage's result. This costs real model tokens, so it is its own task that the user triggers.
- Add a test with no model cost that checks every saved stage against the toolkit's existing backlog, task and diagram checkers.
- **BREAKING (test fixtures only):** replace `toolkit/tests/story/fixtures/sample` with a hand-written mock in `toolkit/tests/story/fixtures/habits/` (the sample's habit tracker domain). The tests that read it (`diagram-checks`, `diagram-scripts`, `write-freeze`, `story-ids`, the tasks tests, `context-map-scripts`, `verify-skill`, `helpers/backlog-tree.mjs`) and `planner/test/helpers/backlog-tree.mjs` move to it, with their assertions moved to the new story IDs. They do not read the sample's recorded stages, which change every time the walk is recorded. The two `diagram-conventions.md` copies, `CLAUDE.md` and the `.gitattributes` LF pin point at the new path.
- Update the wiki's Story to Code page and the toolkit pages, and run `python scripts/check_docs.py`.

## Capabilities

### New Capabilities

- `story-to-code-sample`: the committed sample project, its build script, its saved stage results and the checks that keep them valid.

### Modified Capabilities

- `diagram-conventions`: the "Mock and fixture" requirement names the plan skill's tests as the reader of a mock slice, and the mock slice now lives in the story-to-code sample and is built from the habit tracker's backlog, not from the old test fixture.

## Impact

- New folder `toolkit/sample/story-to-code/` (app source, wiki, saved stages, script, one `package-lock.json`).
- Removed folder `toolkit/tests/story/fixtures/sample/`.
- Changed tests: `toolkit/tests/story/{diagram-checks,diagram-scripts,write-freeze,story-ids,apply-slice-format,tasks-carry,tasks-check,tasks-parse,context-map-scripts,verify-skill}.test.mjs`, `toolkit/tests/story/tasks-fixture.mjs`, `toolkit/tests/story/helpers/backlog-tree.mjs`, `planner/test/helpers/backlog-tree.mjs` and `planner/test/logic/sample-migration.test.mjs`, plus one new staleness test.
- Changed docs: `planner/guidelines/diagram-conventions.md` and its copy `toolkit/skills/jois-story-plan/references/diagram-conventions.md` (the copy is generated by `planner/scripts/sync-skill-logic.mjs`), `CLAUDE.md`, `.gitattributes`, `wiki/Story-To-Code.md` and the toolkit wiki pages.
- No installer change and no change to any skill's behavior. `toolkit/` still imports nothing outside itself, so the zones test is unaffected, and the sample app is not copied by the installer.
- Unchecked, to settle during the change: whether a skill installed at project scope loads ahead of a same-named global skill. The recorded walk depends on it, so the build task checks it first.
